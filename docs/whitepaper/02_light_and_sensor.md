# 2장. 빛, 센서, RAW — 카메라는 무엇을 재는가

> 관련 Phase: 0(촬영 체계, ✅ 완료), 1(센서 특성화)

## 한 줄 요약
이미지 센서는 화소마다 **들어온 빛 알갱이 수를 세는 계수기**이고, RAW는 그 계수값에 오프셋·게인·양자화가 더해진 결과다. 이 과정을 정확히 알아야 노이즈를 모델링하고 HDR을 합성할 수 있다.

---

## 1. 쉬운 비유

비 오는 날 마당에 작은 컵 수백만 개를 바둑판처럼 놓았다고 하자.
- 컵 하나 = 화소. 빗방울 = 광자(빛 알갱이).
- 정해진 시간(노출 시간) 동안 컵에 고인 물을 잰다. 물이 많으면 밝은 곳이다.
- 컵에는 한계가 있다. 넘치면 얼마나 많이 왔는지 모른다(**포화**).
- 물을 재는 자도 완벽하지 않아서 빈 컵을 재도 눈금이 조금씩 흔들린다(**판독 노이즈**).
- 빗방울은 무작위로 떨어지므로, 같은 비가 와도 컵마다 양이 조금씩 다르다(**샷 노이즈**, 3장).
- 컵 위에 빨강·초록·파랑 셀로판을 번갈아 덮으면 색을 구분할 수 있다(**Bayer 컬러 필터**).

## 2. 원리

### 2.1 빛에서 숫자까지
```
광자 ──(양자 효율 QE)──▶ 전자 ──(전환 이득, 아날로그 게인)──▶ 전압 ──(ADC)──▶ 디지털 값(DN)
                          │                                                     │
                     full well에서 포화                               + 블랙 레벨(오프셋)
```
1. **광전 변환**: 광자 하나가 실리콘에서 전자 하나를 만들 확률이 **양자 효율(QE)** 이다.
2. **전하 축적**: 화소는 노출 시간 동안 전자를 모은다. 담을 수 있는 최대 전자 수가 **full well capacity**다.
3. **전환 이득(conversion gain)**: 전자 수를 전압으로 바꾼다. 전자 1개당 몇 µV인지는 화소 회로의 커패시턴스로 정해진다. 4장의 DCG는 이 값을 두 개로 바꿔 쓰는 기술이다.
4. **아날로그 게인**: ADC 전에 신호를 증폭한다. ISO 감도에 해당한다.
5. **ADC**: 전압을 정수로 바꾼다. 이 프로젝트의 기준 모드는 10bit(0~1023)다.

디지털 값 하나를 **DN**(Digital Number)이라고 부른다. 전자 수와 DN 사이 비율(e⁻/DN)이 3장에서 측정할 핵심 상수다.

### 2.2 블랙 레벨(페데스탈)은 왜 있나
빛이 전혀 없어도 RAW 값은 0이 아니라 **64**(10bit 기준)다. 센서가 일부러 더하는 오프셋이다.
- 노이즈는 0을 중심으로 +/− 양쪽으로 흔들린다. 오프셋이 없으면 음수 쪽이 0에서 잘려서 평균이 위로 치우친다.
- 그래서 64를 더해 음수 쪽 노이즈도 기록하고, 처리 단계에서 빼서 되돌린다(**BLC**, Black Level Correction).
- 이 프로젝트의 정규화: `x = (v − 64) / (1023 − 64)` → 0 = 검정, 1.0 = 포화. 분모는 959 코드다.

### 2.3 Bayer 컬러 필터와 쿼드 베이어
- 센서는 색을 모른다. 각 화소 위에 R/G/B 중 하나의 필터를 덮고, 2×2 묶음에 `R G / G B` 식으로 배치한다. G가 둘인 이유는 사람 눈이 초록에 가장 민감하고 밝기 정보의 대부분이 초록에 있기 때문이다.
- 각 화소는 한 색만 재므로 나머지 두 색은 이웃에서 추정해야 한다(**Demosaic**, 6장).
- IMX708은 **쿼드 베이어**다. 같은 색 화소가 2×2로 모여 있다. 이 프로젝트의 기준 해상도 2304×1296은 전체 해상도(4608×2592)의 가로·세로 절반이고, 출력은 일반 Bayer 배열이다.
- 2×2 패턴의 시작 순서(RGGB, BGGR 등)를 **Bayer 순서**라고 한다. 이 값이 틀리면 빨강과 파랑이 뒤바뀐다.

### 2.4 롤링 셔터
- IMX708은 화면 전체를 동시에 노출하지 않고 **행(라인) 단위로 시간을 조금씩 밀어** 노출한다.
- 결과 1: 노출 시간은 **라인 시간의 정수배**로만 정해진다. 요청한 값과 실제 값이 약간 다르다.
- 결과 2: 빛이 빠르게 깜빡이면(PWM 조명) 행마다 다른 밝기를 받아 **가로 줄무늬**가 생긴다. Phase 1 광원 선택에서 중요한 이유다([phase1_equipment.md](../phase1_equipment.md)).

### 2.5 RAW와 ISP 출력의 차이
| | RAW | ISP 출력(JPEG, 일반 영상) |
|---|---|---|
| 값의 의미 | 빛의 양에 **비례**(선형) | 사람 눈에 맞게 휘어진 값(감마) |
| 색 | 화소당 한 색(Bayer) | 화소당 RGB 3색 |
| 비트 | 10~16bit | 보통 8bit |
| 처리 | 없음 | BLC, LSC, Demosaic, WB, CCM, NR, 톤매핑, 감마, 샤프닝… |
| 쓰임 | 측정, 연구, 재처리 | 바로 보기 |

노이즈 모델은 **선형 RAW에서만** 깔끔한 물리 법칙을 따른다. 그래서 이 프로젝트는 RAW를 받아 ISP를 직접 구현한다(6장). Pi ISP 출력은 비교용으로 같은 프레임에서 함께 저장한다.

## 3. 이 프로젝트에서 ✅ Phase 0

Phase 0의 원칙은 **하드웨어 동작을 추측하지 않고 측정한다**였다. 추측했다면 틀렸을 사실들이 실제로 나왔다.

| 확인 항목 | 문서·기대 | 실측 | 영향 |
|---|---|---|---|
| 기본 RAW 포맷 | "10bit RAW" | Pi 5 기본은 **8bit 압축 PiSP 포맷**(`BGGR_PISP_COMP1`) | 압축 RAW는 노이즈 측정에 쓸 수 없다 → 비압축(`SRGGB10` 요청 → `SBGGR16`) 강제, 아니면 촬영 중단 |
| 비압축 RAW 비트 배치 | ? | 16bit에 **MSB 정렬**, 하위 6bit가 0 | `>> 6`으로 10bit 복원 |
| Bayer 순서 | `sensor_modes`는 `RGGB` | 실제 RAW는 **`BGGR`** | 카메라가 180° 회전 장착 → 센서가 상하·좌우 반전 → 2×2 패턴이 뒤집힘. v4l2로 `hflip=1, vflip=1` 확인. **Bayer 순서는 실제 캡처 설정에서 읽는다** |
| 최소 아날로그 게인 | 1.0 | **1.1228** | 센서 게인 공식 `1024/(1024 − code)`에서 최소 code = 112. v4l2 `analogue_gain min=112`. PTC의 "게인 1"은 1.1228로 촬영 |
| 노출 변경 반영 | 즉시? | **5프레임 뒤** | 브래킷 촬영 시 노출 변경 후 5프레임 버림 |
| 실제 노출 시간 | 요청값 | 라인 단위 양자화: 16000 → 15979 µs, 1000 → 988 µs(−1.2%) | 합성에는 **메타데이터의 실제 노출** 사용 |
| 블랙/화이트 레벨 | — | 64 / 1023 (10bit), 포화는 1023에서 깨끗하게 잘림 | 정규화 분모 959 |
| 브래킷 노출비 | 4, 16 | **4.0138, 16.1731** (2% 기준 통과) | 설정값이 아닌 실제 비율로 합성 |

**남은 관찰**: 화소값으로 구한 노출비가 메타데이터 노출비보다 0.4~0.6% 크다(16.24 vs 16.17). 후보 원인은 블랙 레벨 오차, 센서 비선형성, 비율 통계의 편향이었다.
- **Phase 1에서 블랙 레벨은 원인에서 빠졌다.** 다크 프레임 실측 블랙은 63.96 DN으로, 64와 0.04 DN밖에 차이 나지 않는다.
- 대신 짧은 노출에서 응답이 비례식보다 커지는 현상을 찾았다(게인 16, 53 µs에서 +6.4%). 같은 방향의 원인인지 Phase 2 합성 실측에서 확인한다(3장).

**Phase 1에서 추가로 알아낸 센서 사실**
| 항목 | 실측 |
|---|---|
| 실제 최소 노출 | 일반 모드 **53 µs** (센서 정보의 13 µs보다 길다). 센서 HDR 모드 858 µs |
| 노출 단위 | 일반 모드 약 13.36 µs(행 하나를 읽는 시간으로 추정), 센서 HDR 모드 약 71.5 µs |
| 블랙 레벨 | 게인 1.1228에서 63.96, 게인 16에서 64.15~64.21 DN |
| 암전류 | 0.1초 노출에서도 블랙 이동 +0.045 DN. 무시할 수 있다 |

## 4. 엔지니어링 포인트

- **RAW 형식 확인은 첫 번째 일**: "RAW"라는 이름만 믿으면 압축된 값을 노이즈로 측정하게 된다. 촬영 스크립트가 실제 포맷이 `*16`이 아니면 **스스로 중단**하게 만들었다. 잘못된 데이터를 조용히 저장하는 것보다 실패하는 편이 낫다.
- **설정값이 아니라 기록값을 쓴다**: 노출, 게인, Bayer 순서는 모두 카메라가 *실제로 적용한 값*을 프레임 메타데이터에서 읽어 JSON으로 남긴다. 얻을 수 없는 값은 `null`로 두고 추정값을 넣지 않는다.
- **RAW와 ISP 출력을 같은 request에서**: Picamera2의 한 request에서 RAW와 처리된 영상을 함께 받는다. 그래야 "같은 순간"의 비교가 보장된다.
- **원격 자동화**: PC에서 SSH로 Pi에 스크립트를 보내 실행하고 결과를 회수한다(`scripts/pi.sh`). 결과마다 스크립트, 인자, git commit을 `pi_job.json`에 남긴다.

## 면접에서 설명하기

**30초 답변**
> "센서는 화소마다 광자가 만든 전자를 세는 장치이고, RAW는 거기에 블랙 레벨 오프셋과 게인, 양자화가 더해진 값입니다. 노이즈를 물리적으로 모델링하려면 선형 RAW가 필요한데, Pi 5의 기본 RAW는 압축 포맷이어서 비압축 포맷을 강제했습니다. Bayer 순서, 최소 게인, 노출 반영 지연처럼 문서와 다른 동작이 여럿 있어서, 모두 측정해서 확인한 값만 썼습니다."

**예상 질문**
- *블랙 레벨은 왜 0이 아닌가요?*
  → 노이즈가 0 주변에서 음수로도 흔들리기 때문입니다. 오프셋 없이 0에서 자르면 평균이 위로 치우치고 분산도 작게 측정됩니다. 일부러 64를 더해 음수 쪽을 보존하고 처리할 때 뺍니다.
- *Bayer 순서가 왜 문서와 달랐나요?*
  → 카메라가 180° 회전으로 장착되어 드라이버가 센서를 상하·좌우 반전해 읽습니다. RGGB가 뒤집혀 BGGR이 됩니다. v4l2 컨트롤 값으로 반전 상태를 확인했고, 그 뒤로 Bayer 순서를 하드코딩하지 않고 실제 캡처 설정에서 읽습니다. 렌즈 보정 테이블도 같은 반전을 적용해야 한다는 결론으로 이어졌습니다.
- *게인 1.0이 왜 안 되나요?*
  → IMX708의 아날로그 게인 레지스터는 `1024/(1024 − code)` 형태이고 code의 최솟값이 112입니다. 그러면 최소 게인이 1.1228입니다. 메타데이터 값이 이 식의 float32 값과 정확히 같아서 확신할 수 있었고, v4l2 컨트롤의 범위로 한 번 더 확인했습니다.
- *롤링 셔터가 이 프로젝트에 어떤 영향을 주나요?*
  → 두 가지입니다. 노출 시간이 라인 시간의 배수로 양자화되어 짧은 노출일수록 상대 오차가 크고, PWM 조명은 가로 줄무늬를 만듭니다. 그래서 합성에는 실제 노출을 쓰고, PTC 광원은 깜빡임 테스트를 거칩니다.
