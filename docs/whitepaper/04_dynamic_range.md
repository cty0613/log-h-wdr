# 4장. DR 확보: 브래킷 합성과 DCG

> 관련 Phase: 2(DR 확보, 핵심) — ⏳ 예정

## 한 줄 요약
센서 한 번의 노출이 담는 범위를 넘으려면 **노출을 바꿔 여러 장 찍어 합치거나**(브래킷), **한 화소를 두 감도로 동시에 읽어 합친다**(DCG). 두 방식 모두 범위는 넓히지만 합성 경계에서 노이즈가 달라지는 방식이 다르다. 이 차이가 5장 곡선 설계의 출발점이다.

---

## 1. 쉬운 비유

**브래킷 = 같은 장면을 오래 한 번, 짧게 한 번 찍기.**
- 오래 찍은 사진: 어두운 곳이 잘 보이지만 밝은 곳이 하얗게 넘친다.
- 짧게 찍은 사진: 밝은 곳은 살아 있지만 어두운 곳은 검게 묻힌다.
- 화소마다 "넘치지 않았으면 긴 사진, 넘쳤으면 짧은 사진 × 16배"를 쓰면 둘의 장점을 합친 사진이 된다.
- 대가: 짧은 사진은 빛을 1/16만 모았다. 그래서 짧은 사진에서 가져온 부분은 상대적으로 **더 거칠다**. 그리고 두 장 사이에 물체가 움직이면 유령처럼 겹친다.

**DCG(Dual Conversion Gain) = 같은 컵의 물을 두 개의 자로 동시에 재기.**
- 촘촘한 눈금의 짧은 자(HCG): 적은 물을 정밀하게 재지만 금방 끝난다.
- 성긴 눈금의 긴 자(LCG): 많은 물까지 재지만 적은 양은 부정확하다.
- 컵의 물은 **하나**다. 같은 빗방울을 두 번 잰 것이라 빛을 버리지 않고, 시간 차이도 없다.

## 2. 원리

### 2.1 브래킷 합성 알고리즘 (`hdr::bracket_merge`)
노출 시간 t₁ > t₂ (> t₃) 인 N장(2~3장)을 같은 장면에서 찍는다. 노출비 R = t_long / t_short.

화소마다(정규화 값 기준):
1. 긴 노출부터 본다. 값이 포화 임계 **τ = 0.9** 미만이면 그 값을 쓴다.
2. 경계 띠 **[0.8τ, τ] = [0.72, 0.9]** 에서는 긴/짧은 노출을 선형 가중으로 섞는다. 띠 아래쪽 끝은 긴 노출 100%, 위쪽 끝은 짧은 노출 100%.
3. 짧은 노출 값에는 `t_long / t_i`를 곱해 긴 노출의 밝기 단위로 맞춘다. 그래서 합성 결과는 1.0을 넘을 수 있다(최대 ≈ R).
4. 모든 노출이 포화면 가장 짧은 노출 값을 쓰고 **포화 표시 비트**를 세운다.
5. 화소마다 어느 노출에서 왔는지 **출처 맵**(uint8)을 함께 출력한다.

**왜 τ가 1.0이 아니라 0.9인가**: 포화 근처는 비선형성이 있고, 노이즈 때문에 실제 신호가 0.95여도 한 화소는 1.0에 닿을 수 있다. 여유를 둔다.

**왜 경계 띠가 있나**: 딱 잘라 바꾸면 경계를 따라 노이즈 질감이 갑자기 바뀌는 선이 보인다. 섞으면 그 변화가 완만해진다.

**왜 Bayer 도메인에서 합성하나**:
- Demosaic 전에는 화소 하나 = 측정값 하나라서 노이즈 모델(3장)이 그대로 성립한다.
- Demosaic은 이웃 화소를 섞는다. 이웃 중 하나가 포화되면 섞인 값 전체가 오염된다.
- 합성 결과를 다시 "더 넓은 범위의 RAW"로 보고 이후 ISP를 한 번만 적용하면 된다.

**왜 설정값이 아닌 실제 노출비인가**: Phase 0에서 16 ms/1 ms 요청이 실제로는 15979/988 µs였다. 설정값 16으로 합치면 짧은 노출 쪽이 1% 어둡게 붙어 경계에 단차가 생긴다.

### 2.2 확보되는 DR
긴 노출의 바닥 노이즈는 그대로이고, 포화점이 R배 위로 올라간다.
```
DR_bracket ≈ DR_single + log₂R  (stop)
R = 4  → +2 stop,   R = 16 → +4 stop,   R = 64 → +6 stop
```

### 2.3 합성 후 노이즈: 경계에서 계단이 생긴다
짧은 노출의 원래 값을 x_s라 하면, 긴 노출 단위의 값은 x = R·x_s다. 분산은 R²배가 된다.
```
σ²(x) = R²·σ_s²(x_s) = R²·(a·x/R + b) = (a·R)·x + b·R²
```
그래서 합성 결과의 노이즈 분포는 **구간별 직선**이 된다(5.4 스키마).
| 구간 | 출처 | σ²(x) |
|---|---|---|
| x < τ | 긴 노출 | a·x + b |
| x ≥ τ | 짧은 노출 × R | (aR)·x + bR² |

**SNR dip**: 경계 바로 아래와 위에서 SNR을 비교하면, 샷 노이즈가 지배할 때
```
SNR_below² ≈ x / a,    SNR_above² ≈ x / (aR)     →   차이 ≈ 10·log₁₀R dB
R = 4 → 약 6 dB,   R = 16 → 약 12 dB
```
같은 밝기인데 경계 위쪽은 빛을 1/R만 모았기 때문이다. 이 **노이즈 점프**가 단일 노출 곡선으로는 설명할 수 없는 부분이고, H-Log가 노이즈 분포를 그대로 입력으로 받는 이유다.

경계 띠에서는 두 프레임이 독립이므로 가중치 w에 대해 `σ² = w²·σ_L² + (1−w)²·σ_S²`로 섞인다.

### 2.4 DCG의 물리
- 화소의 전하는 **플로팅 디퓨전**이라는 작은 커패시터에서 전압으로 바뀐다. 전압 = 전하 / 커패시턴스.
- 커패시턴스가 작으면(HCG) 전자 1개당 전압이 커서 회로 노이즈의 영향이 상대적으로 작다. 대신 적은 전하에서 전압 한계에 닿는다.
- 스위치로 커패시터를 추가하면(LCG) 많은 전하를 담지만 전자당 전압이 작아 노이즈 영향이 크다.
- 같은 노출의 전하를 두 방식으로 읽어 어두운 곳은 HCG, 밝은 곳은 LCG를 쓴다.

**브래킷과의 결정적 차이**: DCG의 두 판독은 **같은 전자**를 읽는다. 샷 노이즈가 공유된다.
```
전자 단위:  HCG 구간 σ² = n + r_H²,     LCG 구간 σ² = n + r_L²
```
경계에서 바뀌는 것은 판독 노이즈(r_H → r_L)뿐이다. 샷 노이즈가 지배하는 밝기에서는 SNR dip이 브래킷보다 훨씬 작다. 움직임에 의한 유령도 없다. 대신 넓힐 수 있는 범위가 변환 게인 비(보통 수 배)로 제한된다.

| | 브래킷 | DCG | 센서 HDR 모드 (IMX708) |
|---|---|---|---|
| 범위 확장 | log₂R stop (R 자유) | 변환 게인 비·full well로 제한 | 실측 약 5.1 stop (밝은 쪽) |
| 경계 SNR dip | ≈ 10·log₁₀R dB | 작음 (판독 노이즈 차이만) | 첫 경계에서 입력 기준 약 20 dB (근사). 선형 구간도 일반 모드보다 5.5 dB 낮음 |
| 움직임 | 유령 생김 | 없음 | 비공개 |
| 이 프로젝트 | **실측** | **시뮬레이션**(Pi에서 제어 불가) | 특성만 측정, 비교군 (3장 3.2) |
| 출력 | 선형 (합성 후) | 선형 (합성 후) | **비선형 압축** (꺾은선 형태, 역변환 필요) |

### 2.5 DCG 시뮬레이터 (`hdr::dcg_simulate`)
1. 선형 장면(브래킷 합성 결과)을 장면 스케일(e⁻/선형 1.0)로 전자 수로 바꾼다.
2. **포아송 샷 노이즈를 한 번만** 생성한다. 두 판독이 공유한다.
3. HCG/LCG 각각 판독 노이즈(가우시안) 추가 → full well에서 클립 → ADC 비트로 양자화.
4. HCG가 임계 미만이면 HCG, 이상이면 LCG(스케일 맞춤), 경계 띠에서 가중 합.
5. 출력: 합성 이미지 + 해석적 노이즈 분포 JSON.

가정값(변환 게인 비 기본 4, HCG/LCG 판독 노이즈, full well, ADC 비트, seed)은 `configs/dcg_assumptions.json`에 명시하고 리포트에 쓴다. **가정이라는 것을 숨기지 않는 것**이 중요하다.

## 4. 엔지니어링 포인트

- **기준 모델 먼저**: 합성 로직을 Python(float64)으로 단순하게 먼저 쓰고, C++(float32, 최적화)가 같은 결과를 내는지 비교한다. 1e-5는 float32의 유효 자릿수(약 7자리)를 고려한 기준이다.
- **무작위 시뮬레이터를 테스트하는 법**: 출력이 매번 다르므로 값 자체를 비교할 수 없다. 대신 **통계량**을 해석값과 비교한다. 샘플 1e5개면 분산 추정의 상대 표준오차는 √(2/n) ≈ 0.45%라서 ±3%는 우연히 틀릴 확률이 거의 없는 범위다. seed를 고정하면 테스트가 재현된다.
- **상수 입력으로 통계를 본다**: 공간 구조가 있는 장면이 아니라 일정한 값의 큰 이미지에 시뮬레이터를 돌려야 평균·분산을 깨끗하게 잴 수 있다.
- **출처 맵과 포화 비트**: 결과만 내지 않고 "왜 이 값인지"를 같이 내면 경계 오류를 눈으로 디버깅할 수 있다.
- **정지 장면 한정**을 명시한다. 범위 밖의 문제(움직임)를 섞으면 곡선의 효과를 분리해서 볼 수 없다.

## 면접에서 설명하기

**30초 답변**
> "DR 확보는 두 방식을 비교했습니다. 브래킷은 노출을 바꿔 찍어 화소마다 포화되지 않은 노출을 골라 실제 노출비로 스케일을 맞춰 합칩니다. 짧은 노출 구간은 빛을 1/R만 모아서 노이즈가 aR·x + bR²로 커지고, 경계에서 약 10·log₁₀R dB의 SNR dip이 생깁니다. DCG는 같은 전자를 두 변환 게인으로 읽어서 샷 노이즈를 공유하므로 dip이 작습니다. Pi에서 DCG를 제어할 수 없어서 가정값을 명시한 시뮬레이터로 만들고 몬테카를로로 검증했습니다."

**예상 질문**
- *왜 합성을 Demosaic 전에 하나요?*
  → Bayer 단계에서는 화소 하나가 측정값 하나라서 노이즈 모델이 그대로 성립하고, Demosaic이 포화 화소를 이웃과 섞어 오염시키는 것을 막을 수 있습니다.
- *SNR dip은 왜 생기고 어떻게 줄이나요?*
  → 경계 위쪽 값은 빛을 1/R만 모은 짧은 노출에서 오기 때문입니다. R을 줄이거나, 노출을 3장으로 나눠 단계별 R을 작게 하거나, DCG처럼 같은 노출을 다르게 읽는 방식을 쓰면 줄어듭니다. 이 프로젝트는 dip을 없애는 대신 곡선이 그 노이즈 점프를 그대로 반영하게 했습니다.
- *DCG가 브래킷보다 항상 좋은가요?*
  → 움직임과 dip에서는 유리하지만 확장 범위가 변환 게인 비와 full well로 제한됩니다. 넓은 범위가 필요하면 브래킷이 유리하고, 실제 제품은 둘을 섞기도 합니다.
- *무작위 시뮬레이터는 어떻게 테스트했나요?*
  → seed를 고정하고 상수 입력 1e5 샘플의 평균·분산을 해석식과 비교했습니다. 분산 추정의 표준오차가 0.45% 정도라 ±3% 범위면 통계적으로 의미 있는 검사가 됩니다.
- *해석 모델과 실측이 다르면요?*
  → 기준(±10%)을 바꾸지 않고 원인을 분석합니다. 블랙 레벨 오차, 비선형성, 경계 띠의 가중 처리 등을 확인하고, 최종적으로는 실측 분포를 곡선 입력으로 씁니다. 곡선 설계는 "실제 노이즈"에 맞추는 것이 목적이기 때문입니다.
