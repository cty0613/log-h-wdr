결론 세 가지:

  • 합성 후 노이즈 모델은 맞았다. 짧은 노출 값에 노출비 R을 곱한 구간의 분산은 (a·R)·x + b·R²라는 예측이, 실측 200만 화소 단위 구간 9개에서 모두 ±2.1% 안으로 맞았다. 경계 SNR dip도 6.1 dB 예측에 6.2~6.3 dB, 12.5 dB 예측에 12.7 dB였다.
  • 3장 브래킷은 DR이 아니라 중간 밝기 화질을 산다. R=16 2장과 3장은 DR이 14.6 stop으로 같다. 3장은 12.5 dB 절벽을 6.1 dB 두 번으로 나눈다.
  • 짧은 노출이 메타데이터 비율보다 0.5~1% 어둡게 찍힌다. Phase 0에서 본 현상을 정밀 측정으로 재현했다. 노이즈 분포에는 영향이 없고 합성 경계에 0.006~0.016 stop 단차를 만든다. 원인은 미확정이다.

3. 착수 결정

Phase 1 게인 1 노이즈 모델(a = 5.661×10⁻⁵, b = 4.083×10⁻⁷)로 선택지를 먼저 계산하고 정했다.

결정 1 · 16/4/1 ms 3장으로 찍는다

한 번 찍은 3장에서 프레임을 골라 R=4({16, 4}), R=16 2장({16, 1}), R=16 3장({16, 4, 1})을 모두 만든다(hdr_merge --frames). 주 결과는 3장이다.

버린 대안: R=16을 2장으로만. x = 0.9~3.6 구간이 12.5 dB 낮은 SNR로 기록된다.

결정 2 · 노이즈 JSON은 τ에서 점프하는 모델

경계 띠 [0.72, 0.9]의 실제 분산 w²σ_L² + (1−w)²σ_S²는 x의 1차식이 아니다. 점프 모델은 띠 안 노이즈를 작게 봐서 곡선이 코드를 더 촘촘히 쓴다(안전한 쪽). N 차이 1~3%, 필요 비트 같음. 띠의 실측은 정확한 식으로 따로 비교한다.

버린 대안: 띠 시작(0.72)에서 점프 — 띠 안 노이즈를 최대 4.6배 크게 봐서 10 bit에서도 국소적으로 R(x) ≈ 1.9.

결정 3 · DCG 가정값

  • LCG = Phase 1 게인 1 실측: full well 17,666 e⁻, 판독 노이즈 9.96 e⁻(11.29 e⁻에서 ADC 양자화를 뺀 값. 시뮬레이터가 양자화를 따로 한다)
  • HCG = LCG ÷ 변환 게인 비 g(기본 4). 판독 노이즈도 ÷ g — 낙관적 가정으로 명시
  • 장면 스케일 1,104 e⁻/선형 1.0(옵션 B: x = 16에서 LCG 포화)

촬영 계획 수정 · 밝기는 Phase 1 그대로

처음엔 포화 노출을 약 20 ms로 맞추자고 했다. 그러면 16:1 경계의 짧은 노출이 약 1 ms가 되어, Phase 1에서 깜빡임을 무시할 수 있다고 확인한 1.7 ms보다 짧아진다. 밝기를 그대로 두는 대신 가장 밝은 단계의 긴 노출이 약 0.7 s가 됐다.

실제로 701 ms 노출이 일반 모드에서 적용됐다(새 하드웨어 사실, pi_notes.md).

4.2 구현에서 신경 쓴 점

  • 정밀도: 화소 계산은 double로 하고 결과만 float32로 저장한다. 판정 비교(n < 0.72 등)도 double이라 Python과 출처 맵이 비트 단위로 같다.
  • 결정적 난수: DCG는 행마다 (seed, 행 번호)에서 파생한 독립 난수열(SplitMix64 → xoshiro256**)을 쓴다. 1스레드와 4스레드 출력이 비트 단위로 같다(GoogleTest). Poisson(Knuth / PTRS)과 정규분포(Box–Muller)는 직접 구현했다. 표준 라이브러리 분포는 구현마다 결과가 달라질 수 있다.
  • 출처 맵: 하위 4 bit = 고른 프레임 목록 안의 위치, 0x40 = 경계 띠에서 섞임, 0x80 = 마지막 프레임도 τ 이상(포화).
  • 음수 보존: 블랙 아래로 내려간 노이즈 값을 자르지 않는다. 자르면 어두운 곳의 평균과 분산이 치우친다.

6.1 방법: 화소를 국소 밝기로 묶는다

단계마다 세트 두 개를 C++ hdr_merge로 각각 합성해(A, B) 차분 d = A − B로 분산을 낸다. 그런데 플랫필드도 화면 안에서 밝기가 수 % 다르다. 처음 계획대로 단계마다 ROI 평균 하나를 쓰면, 경계 근처 ROI에는 긴 노출 화소와 짧은 노출 화소가 섞여 측정이 흐려진다.

그래서 중앙 512×512, Bayer 채널별로 국소 밝기 x_loc = 9×9 평균((A + B)/2)을 구하고, 화소를 1/16 stop 구간으로 묶어 구간마다 Var(d)/2를 냈다. 모델 기대값은 같은 화소들의 σ²(x_loc) 평균이다. A − B와 A + B는 노이즈 크기가 같으면 서로 상관이 없으므로 합으로 묶고 차로 분산을 재도 치우치지 않는다.

분석 코드는 실측 전에, 노이즈를 알고 있는 가짜 스윕(같은 형식, hdr_merge 실제 호출)으로 먼저 검증했다: 구간 오차 ±1%, dip 0.1 dB 안 (tests/py/test_merged_measure.py).

7. 측정에서 찾은 것

7.1 짧은 노출이 메타데이터 비율보다 어둡게 찍힌다

같은 화소에서 긴 프레임 값 합 ÷ 짧은 프레임 값 합을 메타데이터 노출비와 비교했다. 화소는 다른 세트의 긴 프레임이 0.1~0.7인 곳을 골랐다(이유는 7.4절).

  • 고정 노출 오프셋이 아니다. 같은 4:1 쌍에서 짧은 노출 1.7 ms를 맞추려면 −18 µs, 11.8 ms를 맞추려면 −86 µs가 필요하다. 신호 수준이나 노출 길이에 따른 비선형으로 추정한다.
  • 영향: 합성 경계에서 짧은 노출 쪽이 0.4~1.1% 낮게 붙는다(0.006~0.016 stop). 노이즈 분포에는 영향이 없다.
  • 결정: 스펙(“합성에는 실제 노출비”)대로 메타데이터 노출비를 유지한다. Phase 4 표시 영상에서 단차가 보이면 실효 노출비 보정을 그때 결정한다.

7.2 16:1 띠의 +7.5%는 7.1의 결과다

띠 안의 합성값은 (1−w)·1%만큼 낮다. 그 값으로 구한 국소 밝기 x_loc도 조금 낮아지고, 모델 분산은 낮은 x에서 평가된다. 16:1 띠는 분산이 x에 따라 매우 가파르게 변하므로(띠 폭 0.18 안에서 약 18배) 작은 밝기 오차가 몇 %의 분산 과소평가가 된다. 이 효과만으로 계산한 예측과 실측을 비교했다.

띠분산 기울기쓴 노출비 편차예측 (구간별)실측 (구간별)

세 띠의 순서와 크기가 맞는다. 실측이 세 곳 모두 예측보다 2~3% 낮은데, 이 차이는 긴 노출 포화 직전의 PTC 휨(분산 약 5% 낮음, 그림 3에서 x 0.6~0.72의 −4~−6%)과 같은 방향·크기다. 분석 코드를 먼저 가짜 데이터로 검증해 두었기 때문에, 이 값이 분석 버그가 아니라 데이터의 성질이라고 보고 추적할 수 있었다.

7.3 초록 포화 자리의 파랑 화소: blooming

긴 노출 구간 위쪽 끝(x 0.64~0.72)에서 B 채널만 −9~−10%다. 이때 이웃 초록은 x ≈ 1.2~1.3으로 이미 포화돼 있다. Phase 1에서 본 넘친 전하의 번짐과 같은 현상이다. 구간 전체에는 −3.2%로만 들어가므로 합성 규칙(화소 단위 τ 판정)은 스펙대로 유지한다.

7.4 분석 쪽 버그 하나: 선택 편향

처음 노출비 검사는 “짧은 프레임 값이 0.02보다 큰 화소”만 골랐다. 가짜 데이터에서도 최대 8% 틀렸다. 노이즈가 우연히 위로 튄 화소만 남기 때문이다. 고르는 기준을 노이즈가 독립인 다른 세트의 프레임으로 바꾸자 오차가 0.04% 아래로 사라졌다. 그 정밀도 덕분에 7.1의 0.5% 편차를 잴 수 있었다.
