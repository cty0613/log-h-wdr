Phase 3의 핵심 산출물은 곡선 JSON 9개(configs/curves/)와 그것을 적용하는 C++ 곡선·LUT다. 보관 경로(Phase 4)는 configs/curves/hlog_R16.json을 쓴다.

결론 세 가지:

  • H1 성립. 차이는 “압도적”이 아니라 약 30%다. 브래킷 R=16 데이터 10 bit에서 H-Log의 최대 R(x)는 0.49, 가장 좋은 비교 곡선 HLG는 0.71이다. HLG가 강한 이유는 아래쪽 절반이 √E라서 샷 노이즈와 모양이 같기 때문이다.
  • 노이즈 매칭의 이득은 노이즈가 점프하는 합성에서 나온다. DCG 데이터에서는 맞춘 H-Log와 단일 노출 모델 H-Log가 사실상 같다(0.254 vs 0.255). DCG 노이즈는 거의 √x 모양이라 단일 모델 곡선으로도 맞기 때문이다.
  • H2: 필요 비트는 DR보다 합성 프레임 수로 정해진다. 한 노출이 보탤 수 있는 단계 수가 약 2√(포화 전자 수) ≈ 266으로 제한된다. 2장 브래킷은 DR을 6 stop 넓혀도 9 bit, 3장은 10 bit다. 합성을 무시하고 단일 노출 모델로 곡선을 만들면 12 bit가 필요하다.

2. 읽는 법

각 절의 파란 테두리 상자 “백서 연결”은 기술백서의 어느 장·절이 이 결과를 설명하거나 예측했는지 가리킨다. 전체 목록은 10절 대조표에 있다.

표시뜻
확인백서의 원리·예측이 결과와 맞았다.
보정원리는 맞지만 조건이나 수치를 고쳐야 했다. 백서에 반영했다.
새 사실백서가 다루지 않은 것을 새로 찾았다.
미해결다음 Phase에서 확인한다.

용어 세 개

  • x: 긴 노출 기준 정규화 선형값(1.0 = 긴 노출 포화). 그림의 가로축 stop = log₂x.
  • R(x) = 양자화 간격 Δx / 노이즈 σ(x), Δx = 1/((2^bits − 1)·C′(x)). R ≤ 1이면 양자화 계단이 노이즈보다 작다. 최악 SNR 손실은 10·log₁₀(1 + R²/12) dB.
  • N = ∫dx/σ(x): 노이즈 1σ 간격으로 구분할 수 있는 단계 수. 노이즈 매칭 곡선은 R이 상수 N/(2^bits − 1)이고, 필요 비트 = ⌈log₂N⌉.

3. 착수 결정: 비교 규칙을 결과 전에 고정

곡선 비교는 규칙에 따라 결론이 바뀐다. 특히 입력 스케일을 비교군에 불리하게 고르면 결론이 무의미해진다. 그래서 다섯 가지를 계산 전에 decisions.md에 고정했다.

4. H-Log 곡선

양자화 계단을 노이즈 σ(x)에 비례하게 놓으면 모든 밝기에서 R이 같아진다. 그 조건을 풀면 곡선은 1/σ를 적분한 것이다.

C(x) = k·∫₀ˣ dt/σ(t),   k = 1/N,   N = ∫₀^{x_max} dt/σ(t)     (C(x_max) = 1)

구간 i (σ² = aᵢ·t + bᵢ):
  ∫_{xᵢ}^{x} dt/σ = 2(x − xᵢ) / (√(aᵢx + bᵢ) + √(aᵢxᵢ + bᵢ))     ← a → 0에서도 안정한 형태
역함수 (u = (V − cᵢ)/k):
  x = xᵢ + u·(√(aᵢxᵢ + bᵢ) + aᵢu/4)                                ← 닫힌 형태, 반복 계산 없음

Python이 k와 구간마다 시작 값 cᵢ = C(xᵢ)를 계산해 JSON으로 넘기고, C++은 적용만 한다. C++은 읽을 때 C(x_max) = 1을 다시 확인해 파라미터가 어긋나면 거부한다.

판정: 8 / 10 / 12 bit 모두 성립. 맞춘 H-Log의 최대 R은 가장 좋은 비교 곡선(모두 HLG)의 0.69배다.

6.1 해석

  • HLG가 강한 이유: HLG 아래쪽 절반(E ≤ 1/12)은 V = √(3E)다. 샷 노이즈도 σ ∝ √x라서, HLG는 우연히 노이즈 매칭 곡선과 같은 모양을 반쯤 갖는다. 위쪽 로그 구간에서 R이 커져 최댓값을 만든다.
  • 8 bit에서는 아무도 충분하지 않다(모두 R > 1). H-Log는 손실을 전 구간에 고르게 나눠 최댓값이 가장 작지만, R > 1 구간 길이는 HLG(13.4 stop)가 조금 짧다. 실제 영향은 Phase 5의 8 bit 대조군에서 본다.
  • 합성을 무시한 곡선은 코드를 잘못 나눈다: 단일 모델 H-Log는 노이즈가 작은 긴 노출 구간에 코드가 모자라고(R ≈ 1.02), 노이즈가 큰 짧은 노출 구간에는 남는다.
  • 경계를 걸친 코드 하나(보조 지표): 기울기가 꺾이는 점에서 코드 하나가 위쪽 넓은 간격까지 덮는다. 노이즈를 점프 모델로 보면 10 bit에서 0.724(HLG 0.706)까지 커지지만, 실제 합성 데이터는 경계 바로 아래가 띠라 노이즈가 이미 커져 있어 그 노이즈로 보면 0.539다.

DCG는 두 판독이 샷 노이즈를 공유해 구간이 바뀌어도 기울기 a가 같고 판독 노이즈만 바뀐다. 그래서 노이즈가 거의 √x 모양이고, 단일 노출 모델(역시 √x)로 만든 곡선과 모양이 같다. 노이즈 매칭의 이득은 브래킷처럼 노이즈가 점프하는 합성에서 나온다 — 원래 가설보다 구체적인 결론이다.

7. H2: DR 대비 필요 비트

7.1 왜 프레임 수가 정하나

짧은 노출 구간 하나가 보태는 단계 수는

∫_{τR'}^{R} dx/√(aR·x + bR²) ≈ (2/(aR))·√(aR·R) = 2/√a = 2√(포화 전자 수) ≈ 266

로, R과 거의 무관하다. 짧은 노출이 빛을 1/R만 모으는 대신 그 구간이 R배 넓어서 서로 상쇄된다. 그래서 N ≈ 프레임 수 × 266 정도가 상한이고, 2장이면 512 아래(9 bit), 3장이면 1024 아래(10 bit)다.

H2 결론: “확보한 DR에 따라 필요 비트가 정해진다”는 가설은 합성 노이즈를 모델링하면 성립하지 않는다. 필요 비트는 DR이 아니라 합성 프레임 수(모은 전자 용량의 합)로 정해진다. 이 프로젝트의 브래킷 R=16(3장)은 10 bit에서 R ≈ 0.48로 양자화 기준의 여유가 약 2배다. 그 여유가 압축 후에도 남는지는 Phase 5에서 본다.

백서 연결

  • H2 가설 “DR에 따라 필요 비트가 정량적으로 정해진다” — 정량적으로 정해지지만 변수는 DR이 아니라 프레임 수 보정

hlog_single161,0410.38 LSB327,68011,521 / 0예5.7e-8
hlog_single_g112440.10 LSB327,68011,513 / 0예5.7e-8

검사 점은 모든 인덱스 점 i와 i + {0.25, 0.4999, 0.5001, 0.75}(인덱스 반올림 경계 양쪽)이다. 1 LSB 오차(약 0.5%)는 인덱스 반올림(최대 반 칸)이 출력 코드의 반올림 경계를 넘길 때만 생긴다. 곡선이 가장 가파른 x = 0에서도 반 칸이 0.45 LSB(R16 2장) < 1 LSB라서 2 LSB 오차는 원리상 생길 수 없다. 그래서 보간은 넣지 않았다.

백서 연결
  • 5장 2.8 “균등 인덱스는 x = 0 근처에서 1 LSB 기준에 가까울 수 있다(예시 값으로 1.8 LSB/칸)” — 실측 노이즈로는 최대 0.91 LSB/칸, 기준 통과 보정
  • 5장 4 “반올림 규칙 명시” — fixed.hpp와 docs/fixed_point.md 일치, 음수·NaN·포화 테스트 확인

9. 진행 중 발견과 수정

R(x) 계산 방법을 바꿨다

처음 정한 방법(복호 레벨의 중앙 차분)으로 재자, 노이즈 매칭 곡선(R이 상수 0.483이어야 함)의 최댓값이 0.72로 나왔다. 0.72 = 0.483 × 1.5. 노이즈가 2배 뛰는 경계 점에서 위아래 간격이 평균된 것이다. 중앙 미분도 같은 이유로 0.617이 나왔다.

스펙 6.4의 미분 정의를 쓰되, 각 점에서 경계를 넘지 않는 쪽 한쪽 미분으로 바꾸자 0.485로 해석값과 맞았다. 경계를 걸친 코드의 효과는 지우지 않고 보조 지표로 남겼다(6.1절).

표준 곡선 테스트가 처음 실패했다

  • Rec.709: L = 0.018에서 0.081 기대 → 0.08125. 반올림된 상수 때문에 두 식이 끊긴다(표준의 성질).
  • S-Log3 90% 백색: 598 기대 → 597.9. 문서 값은 반올림 코드.
  • S-Log3 양자화 왕복: 코드 0 → 95. 코드 0~94는 음수 입력이라 정의역 [0, x_max]에서 쓰이지 않는다.

세 경우 모두 구현을 고치지 않고 표준의 성질을 확인해 테스트 기대값을 고쳤다.

DCG에서 사실상 동점

결정 3의 판정 기준(“작으면 성립”)은 바꾸지 않았다. 대신 결론 표에 “차이 < 2%, 사실상 동점”을 함께 적어 숫자만 보고 과장하지 않게 했다.

Phase 0 뼈대 테스트

curve_eval이 실제 곡선 JSON을 요구하게 되면서, 임의 config를 넣던 Phase 0 뼈대 테스트가 실패했다. 테스트가 확인하던 것(run_cpp 래퍼, run.json 기록)은 그대로 두고 입력만 실제 곡선 config로 바꿨다.

10. 백서 주장 ↔ 결과 대조표

백서주장판정결과
5장 2.3R(x) = Δx/σ(x) ≤ 1이면 양자화 손실이 노이즈보다 작다확인지표로 사용. 계산 방법은 미분 정의로 확정(9절)
5장 2.4노이즈 매칭 곡선은 R이 상수확인해석 0.483, C++ 측정 0.485 (10 bit)
5장 2.5구간별 닫힌 형태, 값 연속·기울기 불연속확인경계 ±1e-12 연속, C′·σ = k (상대 2e-5 안)
5장 2.5순수 로그(σ ∝ x 가정)는 샷 노이즈에 맞지 않는다확인S-Log3 10 bit 최대 R 1.17 vs H-Log 0.49
5장 2.6필요 비트 = ⌈log₂N⌉, 한 노출의 상한 2/√a확인2/√a ≈ 266, 2장 R = 64까지 9 bit
5장 2.6예시 값(a = 0.0012)으로 브래킷 R=16에 7 bit보정실측 노이즈로 9 bit(N 494, 3장). 백서 표를 실측값으로 교체
5장 2.7HLG 아래쪽 √E는 샷 노이즈와 같은 모양확인그래서 가장 강한 비교 곡선(10 bit 0.71)
5장 2.7공정한 비교를 위해 스케일 규칙을 먼저 정한다확인결정 1~3을 계산 전에 고정, 결과를 본 뒤 바꾸지 않음
5장 2.8균등 인덱스 LUT는 x = 0 근처에서 1 LSB에 가깝다보정실측 노이즈로 최대 0.91 LSB/칸, 오차 최대 1 LSB, 2 LSB 0건
H1합성 노이즈에 맞춘 H-Log가 단일 노출 곡선·S-Log3·HLG보다 손실이 작다확인브래킷: 모든 비트 성립(HLG의 0.69배). DCG: 단일 모델과 동점
H2DR에 따라 필요 비트가 정해진다보정DR이 아니라 프레임 수가 정한다. 합성을 무시하면 DR에 따라 늘어난다(12 bit)
—노이즈 매칭의 이득이 생기는 곳새 사실노이즈가 점프하는 합성(브래킷). √x 모양 노이즈(DCG, 단일)에서는 √ 모양 곡선이면 충분
